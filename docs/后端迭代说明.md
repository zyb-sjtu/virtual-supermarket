# 第一阶段后端迭代说明（v1.3）

> 本文记录 v1.3 业务交付。v1.4 已进一步适配 PostgreSQL、迁移现有数据，并验证不同端口的独立数据库服务；当前部署状态以 [PostgreSQL运行与隔离验证](PostgreSQL运行与隔离验证.md) 为准。

## 阶段目标与交付

本轮围绕十二周计划第一阶段的传统业务闭环补充商品、订单、库存与数据维护。第二阶段的身份权限与独立数据库部署、第三阶段的 Agent、第四阶段多门店隔离尚未实施。

| 计划内容 | 本轮交付 | 当前范围 |
| --- | --- | --- |
| 商品自由上架、分类、分区 | SKU 唯一约束、资料/价格/图片编辑、上下架、名称/SKU 搜索 | 固定分类，分区为可编辑文本，暂无分类/货架独立管理 |
| 商品批量维护 | 1–100 商品 JSON 事务导入、模板下载 | 首次新增，冲突整批回滚；不含批量更新与图片导入 |
| 交易与订单 | 单商品购买生成订单、多商品下单 API、订单分页、整单取消 | 网页无购物车，没有支付及配送状态 |
| 库存管理 | 补货、原因必填的正负调整、完整台账、取消返还 | 数量为整数，无批次/保质期/供应商管理 |
| 并发防御 | 条件扣减、事务回滚、请求幂等、编辑版本校验 | SQLite 同一时间串行写入，未做生产容量压测 |
| 记录维护 | 成交快照、审计事件、CSV 导出 | 无账号，审计无法标识真实操作人 |
| 数据维护 | 在线一致备份、恢复前校验、现库安全备份、一致性检查 | 本机文件型数据库，未部署云数据库 |
| 测试与 CI | 28 项本机测试、前端交互验证、CI 工作流配置 | 远端 CI 尚未执行 |

## 数据模型

| 表 | 主要信息 | 关系/用途 |
| --- | --- | --- |
| `products` | ID、SKU、名称、价格分、库存、分类、分区、单位、图片、状态、版本 | 商品当前状态 |
| `movements` | 购买/补货数量、成交单价、名称/SKU/单位快照、结余、订单关联 | 保留旧接口与历史交易记录 |
| `orders` | 请求编号、内容指纹、金额、状态、取消时间/原因 | 一笔交易；取消状态为终态 |
| `order_items` | 商品 ID、成交名称/SKU/单位/价格、数量、结余 | 订单明细快照，防止改价改名影响历史 |
| `inventory_entries` | 有符号变化量、结余、事件类型、原因、订单关联 | 每次库存变化的统一台账 |
| `audit_events` | 事件、实体、请求编号、修改前后 JSON、时间 | 商品、库存、订单等操作追踪 |
| `api_requests` | 接口作用域、请求编号、指纹、结果 JSON | 新接口的幂等结果 |
| `product_creations` / `product_status_changes` | 上架请求、状态变更请求和记录 | 保留旧版本幂等与上下架历史 |
| `schema_migrations` | 已执行的迁移版本 | 防止历史订单、期初与台账重复补录 |

所有时间以 UTC 保存，前端使用本机时区显示。没有账号信息，审计是业务事件记录，并非具备真实人员身份的合规审计系统。

## 核心业务流程

### 下单

校验商品与数量 → 开启写事务 → 查询请求去重 → 校验全部商品在售与库存 → 读取当前价格并计算金额 → 条件扣库存 → 写订单/明细/交易记录/台账/审计 → 提交。

任意商品不足时整单回滚。客户端价格不参与成交计算。同一请求重试返回既有订单，即使该订单之后已取消也不重新扣库存。

### 取消订单

校验原因与请求编号 → 开启写事务 → 判断订单状态 → 每项恢复原购买数量 → 写取消返还台账 → 更新订单状态与取消信息 → 审计与请求结果 → 提交。

并发取消由事务串行化；已取消订单再次请求不会重复返还。净销售额按订单原成交金额冲销，不受商品之后改价影响。

### 编辑资料

携带读取时的 `version` → 事务内判断版本 → 更新字段并版本加一 → 保存前后快照与幂等结果。另一请求已经修改时返回 409，提示刷新重填。库存、SKU、单位和状态不能通过资料编辑直接覆盖。

### 调整库存

使用 `delta` 指定正负变化、必填原因 → 条件更新库存 → 同事务写台账、审计及幂等结果。调整不能使库存小于零；保留补货与购买的专用业务接口。

## 维护及一致性

- 备份使用 SQLite `Connection.backup`，覆盖主库与 WAL 已提交内容，拒绝覆盖已有备份。
- 恢复先在临时数据库检查原备份并升级，检查业务一致性，再备份现库并恢复；运行中的主服务锁阻止恢复。
- 检查包含物理完整性、外键、每个商品累计台账与当前库存、相邻台账结余、订单明细金额、取消返还数量。
- 原始历史商品名称/单位未保存的部分以迁移时资料补齐，历史成交价格保持不变；不能声称恢复了从未记录的信息。
